# Website experience engineering — 28 September 2026

## Findings and changes

- Enquiry validation previously returned a generic error and asked visitors to use Back. Error responses now preserve submitted fields, identify invalid inputs, focus an accessible error summary, and keep navigation/assets working on the API response URL. Responses containing entered details are no-store and noindex.
- POST/redirect/GET alone did not prevent repeated POSTs. Transactional receipt keys now return the original reference on retries without repeating notifications or enquiry-source counting. Reusing a key with altered data returns a conflict. JavaScript-free identical submissions are deduplicated for 15 minutes; keyed receipts are retained for seven days. Existing submission rate limits remain enforced.
- Submission controls previously could stay disabled after slow navigation. Shared busy handling prevents repeated clicks, restores controls after a 15-second wait without claiming success, and resets on Back navigation. Feedback retains its existing server-side duplicate protection.
- Contact directions were below the entire enquiry form. Visiting information is now first; request copy is shorter. Partnership and insurance links select the appropriate enquiry category, with an editable selection.
- Arrow typography and button shapes varied between pages. Original local SVG direction icons, shared focus/hover/active/disabled states, and consistent control sizing now cover public pages. No icon library or external dependency was added. Existing service illustrations are original SVGs.
- Homepage services repeated bordered cards, category labels and identical prompts. Simplified service links preserve descriptions and clear heading affordances. Removed 2,813 bytes of CSS for retired homepage sections.
- Menu closes with Escape or an outside click and resets on browser history navigation. Current totals API failure now explicitly labels the dated fallback snapshot.

## Verification

28 backend test groups passed, covering enquiries, rate limits, persistence, receipts, moderation, confirmed totals, authentication, CSRF, backups, and related workflows. New cases cover retry deduplication, conflicting retry content, preserved/escaped invalid input and no-JavaScript retry fallback.

Cookie-choice, interaction-state and JPEG metadata checks passed. The interaction checks cover double clicks, slow responses, stable retry keys and Back-navigation reset.

Browser checks used synthetic local enquiries with mail captured locally. The validation → correction → saved receipt → Copy reference workflow passed. Keyboard menu open/Escape and partnership category routing passed. Home, contact, services and reviews had no horizontal overflow at 320, 390, 768 and 1280 pixels. Static internal links and asset references: 341 checked.

## Performance and limits

Measured gzip sizes: homepage HTML 4,434 → 4,388 bytes; contact HTML 3,207 → 3,221; shared JS 1,422 → 1,939; feedback JS 1,461 → 1,348; homepage CSS 3,480 → 2,941. New shared experience CSS and SVG sprite add 1,459 and 202 bytes respectively. These are reproducible compressed source sizes, not measured field performance. No mobile-network speed or broad accessibility certification is claimed.

External maps, WhatsApp and email links retain their existing destinations. No real messages or public reviews were submitted for testing. Clinical HMIS code, approved services, confirmed production totals, cookie-consent choices and private configuration remain outside this change. Existing authenticated admin behaviour is covered by backend tests; this release does not redesign every admin screen.

## Operations

Incremental publication contains public source only. Pre-release file copies and before/after screenshots are retained in the local release workspace. The new enquiry receipt table is additive and included by the existing whole-database backup. Rollback should restore changed source files while preserving live messages, comments, media and totals history.

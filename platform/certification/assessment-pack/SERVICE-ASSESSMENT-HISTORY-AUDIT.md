## Implementation contract for the next batch

1. Add an append-only structured revision model bound to the record, encounter, visit and facility. Retain a complete typed snapshot, template version, risk/follow-up, recorder/session, server time, version and predecessor. An initial migrated current snapshot must be explicitly labeled as a baseline captured during migration, with unavailable historical revision/session facts left unknown. Do not invent old content from hashes or overwrite historical audit events.
2. Keep the mutable current record for compatible readers, but atomically append the next snapshot, advance the original revision/signer coupling, update the current projection, and append value/session audit evidence in one transaction. A failed append or audit must leave all four unchanged. No new automatic retry without a separate idempotence contract.
3. Use database uniqueness and relational integrity for per-record ordering/predecessor/context, and appropriate database write restrictions for append-only rows. A cross-row `CHECK` expression is not a substitute for relational constraints. Verify restrictive delete behavior and direct update/delete rejection using the intended application database role, including migration/restore tooling behavior. Superuser immutability is not claimed.
4. Define separate draft edits and post-signature amendments. Post-signature corrections must retain the signed original, explicit reason, correcting actor/time and the exact record/revision being amended. Decide policy for CORRECTED and clinically closed encounters before exposing controls; preserve MFA, authorization, facility isolation and current clinical-closure gates. Engineering design is not clinical approval.
5. Return bounded, deterministically ordered history with explicit truncation/paging. Every read must pass current permission/facility and disclosure auditing. Show recorder/time/reason/revision and missing-value labels; use the same field grouping as entry/current views at desktop, tablet, 390 and 320 pixels. Print must identify the selected original/current revision and associated amendments, exclude drafts/controls, and retain multi-page content.
6. Test concurrent first saves, stale editors/signers, duplicate/changed-payload requests, append/audit failures, final-state races, foreign revision references, legacy baseline truthfulness and restored data. Keep existing 55-migration baseline evidence separate from new migration evidence. Unsaved navigation/reload protection remains the next independent UI item; this audit does not implement it.

## Existing controls retained and checked

The route requires encounter.write before opening its transaction. Mocked 401/403 authorization denials prevent database access; actual auth regressions remain included separately. Visit reads and writes use actor facility, linked patients must belong to that facility and be active, and self-links fail. Missing/foreign visits, signed assessments, wrong service/clinic, stale templates, unknown fields, missing required inputs and unsupported actions fail before save/audit. One Serializable transaction contains assessment, queue transition and success audit. Audit errors withhold success in a modeled commit boundary. Known aborts currently return 409 after one attempt; this audit does not introduce retry or claim native rollback proof.

GET performs disclosure auditing before returning private/no-store data and withholds it on audit failure. Browser checks confirm reception-only navigation hides this clinical destination, a 409 preserves both the typed draft and original saved snapshot, and a successful POST remains confirmed when the following metrics refresh fails. These are intercepted synthetic browser responses, not server authorization or native durability evidence.

## Next implementation contract

1. **One lifecycle contract:** reuse established closed-visit semantics (DISCHARGED/COMPLETED/CANCELLED or clinicallyClosedAt) in both write actions. Reject SIGNED/CORRECTED assessment replacement and return the retained applicable record with authoritative encounter state. Never create a draft to evade a final encounter. LINK_PATIENT remains a distinct command, with its existing patient checks and permissions.
2. **Require the operator's observed record state:** design an explicit mandatory nullable revision contract for a first save versus an existing record. Bind it to visit, encounter identity/state and assessment identity/version; templateVersion alone is insufficient. Compare inside the transaction and atomically guard the write. Include simultaneous first saves, two editors, stale unchanged payload, sign/discharge races, and an encounter replaced after loading. Retain the original expected revision on any later known-abort retry. Do not use last-write-wins or transparent browser resubmission to hide conflicts.
3. **Define ambiguous-response behavior:** a repeat must either be a verified actor/facility/payload-bound replay or return a conflict requiring review. Do not promise idempotence based only on matching field names, a timestamp, or a later reread. Preserve the original draft and show the current saved record separately.
4. **Fail closed on read errors:** disable writes until a successful current load. Show a retry action and explicit loading/error/read-only states. Preserve unsaved data during conflict/refresh recovery; prompt before explicit discard or navigation. A saved-then-refresh-failed message must distinguish those two outcomes without inviting duplicate submission.
5. **Align entry, saved and print views:** compact blue-and-white layout; matching field order/columns, explicit missing values, recorder/time and patient/visit identity. Print only confirmed saved data with attribution and identity, excluding editable drafts and commands. Verify desktop, tablet, phone, keyboard/touch, print media and actual multipage PDF output.
6. **Evidence and history:** include actor/session/facility and canonical before/after value fingerprints in the same transaction. Hashes alone cannot reconstruct earlier content. Design immutable assessment revisions/attributable amendments separately if a schema change is needed; a database release then requires a fresh verified backup and migration safeguards. Do not reuse the October 15 exception or claim an unimplemented history as complete.

For the correction, first turn the known-gap reproductions into rejection/retention acceptance tests. Add native PostgreSQL stale-update, simultaneous-create, closure/sign races and forced-audit-failure assertions, including unchanged records/queues/history on failure and one durable success. Verify authorization/MFA, facility isolation and exact-source CI/browser behavior before normal push/release. No blanket retry replacement or clinical threshold changes belong in that batch.

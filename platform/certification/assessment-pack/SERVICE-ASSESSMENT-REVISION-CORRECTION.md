## Contract

Assessment GET returns `assessmentRevision`: explicit null only when there is no applicable encounter, otherwise a SHA-256 token over the visit identity, encounter identity/status/update time and assessment identity/update time/template. SAVE_ASSESSMENT must supply its original `expectedRevision`; omission returns 428, invalid syntax 422, and a changed observed state 409. Permission, facility, template, input, safeguarding, closed-visit and final-encounter guards still apply. A revision is not an authorization credential. Matching values do not authorize a replay with a stale revision.

Within the existing single Serializable transaction, the server compares the original token, conditionally updates the observed open visit, and conditionally advances a draft encounter's update time monotonically. New encounters remain inside that same boundary. Every assessment save now advances the consultation revision already checked by notes, diagnosis and SIGN commands. Assessment upsert, queue transition and success audit commit together. No automatic transaction retry or broad retry-policy change was added.

The browser keeps the original revision with its typed draft. Conflict, missing-precondition and ambiguous transport/server failures require review. Loading the latest saved assessment displays that snapshot separately, keeps typed entries and does not adopt a newer revision. Explicit replacement, with confirmation, copies the reviewed saved fields and revision into the editor. A failed review disables writes. No automatic resubmission occurs. A separate worklist-refresh error still preserves confirmed save success. Related-record refresh cannot silently advance the draft's revision. Blue-and-white entry/saved positions, attribution, missing-value labels and saved-only printing are retained.

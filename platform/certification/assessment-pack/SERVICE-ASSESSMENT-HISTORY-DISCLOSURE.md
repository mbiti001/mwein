# Structured assessment history disclosure — 22 October 2026

This engineering batch adds read access to retained snapshots. It does not change clinical rules, approve clinical use, deploy a release, or complete the history presentation/amendment contract.

`GET /api/service-points/history?visitId=<uuid>&recordId=<uuid>` requires the existing `encounter.write` permission, including password/MFA gates. The record must belong to the supplied visit and authenticated facility, on a DRAFT, SIGNED or CORRECTED encounter. Every revision query independently includes the verified record, encounter, visit and facility. A foreign or missing record returns the same 404 without querying revisions. Signed/corrected and clinically closed records remain readable; no editing gate is relaxed.

The response contains at most 20 retained snapshots, descending by the unique per-record version. It returns `hasMore` and `nextBeforeVersion`; request the next page using `beforeVersion=<returned value>`. The strict positive integer cursor excludes that version. Newer appended saves cannot change which older versions fall below it. No offset or client-selected page size is accepted. Invalid, unknown or repeated query parameters fail with 422 before reading records. The extra look-ahead row is neither disclosed nor included in the disclosure fingerprint.

Returned snapshots retain their IDs, versions, predecessor, kind, template, structured values, risk/follow-up, source creation/update timestamps, capture timestamp and recorder ID/display name. Null/false/blank values remain distinct. The recorder name is the current name on the linked user; this store does not retain historical display-name spelling. Session identifiers stay server-side; `sessionAttribution` reports `RECORDED` or `NOT_AVAILABLE`. A migration baseline remains `MIGRATION_BASELINE`, with its original session unavailable and source time distinct from migration capture time. It does not establish earlier values or the original creation time of missing revisions.

Every successful page, including an empty page, awaits the existing `SERVICE_POINTS` disclosure event with the authenticated actor/session/facility and a fingerprint of the visit, record and returned snapshot IDs. No clinical text enters that event. Failed auditing or database access returns no snapshots; success and errors are private/no-store. No automatic retry was introduced. An empty initial page explicitly reports `NO_RETAINED_SNAPSHOTS`; other pages report `RETAINED_SNAPSHOTS_ONLY`. Neither label promises completeness of pre-capture history. The existing worksheet/current-record API is unchanged.

## Verification and limits

Unit checks exercise permission/MFA-denied entry, record/visit/facility scoping, exact page bounds and audited IDs, cursor validation, inter-page append behavior, baseline/session truthfulness, absent values, empty pages and read/audit failures. Native PostgreSQL verification compares persisted values and timestamps, independently reconstructs disclosure fingerprints and session ownership, rejects unauthenticated/reception/foreign-facility reads, injects a disclosure-audit failure, confirms retained rows are unchanged, and pages over accepted API saves with a new version inserted between reads. Synthetic SIGNED/CORRECTED/closed states are established using fixture SQL, not clinical sign-off. The mandatory MFA fixture explicitly checks this endpoint before enrollment.

The authenticated browser capture scenario now reads both real retained versions, checks attributed original/current values, queries an older page, rejects an invalid cursor and verifies 401 after clearing its session. Existing desktop/tablet/390/320 and saved-only print regressions remain. No history UI or new print design is claimed in this batch. Source/build/full-suite/CI evidence is recorded in the companion JSON and workflow log.

Development failures retained: the first new unit run had 22 passing tests and one assertion failure because it expected a missing `sessionId` property to exist with value undefined. The corrected assertion explicitly requires absence. Type checking also caught a mock returning an ordinary Promise instead of PrismaPromise; the mock boundary was corrected. No runtime gate or timeout was relaxed.

The initial full local browser run passed 155 cases and failed the extended capture case with 401 when Playwright's separate APIRequestContext read history, although the page had just authenticated and saved both versions. The test now makes these requests through `fetch` in the browser page, exercising the secure loopback cookie path used by the application. The failure trace and initial results remain retained; no cookie setting, permission gate or assertion was weakened. Windows CRLF working-copy/initial-archive hash mismatches are also retained; the canonical LF source audit passes without changing existing route fingerprints or adding exceptions.

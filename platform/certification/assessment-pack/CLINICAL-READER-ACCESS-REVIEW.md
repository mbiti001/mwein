## Limits and remaining work

- Patient history returns the latest 20 visits, 20 appointments and 20 referrals without a truncation marker; problem lists and nested orders are not independently paginated. Its patient/exclusion identifiers are not explicitly UUID-validated in this handler. These are retained limitations, not claimed complete input/pagination controls.
- Summary searches return 25/50 visits without a truncation marker. A summary can include an explicitly DRAFT encounter when no signed one exists. It is an authorized working record, not automatically a signed discharge document. Orders remain in the API record with their statuses; display filtering must not be mistaken for API redaction.
- Current confidential-note removal covers the existing `plan.confidentialNote` field. This does not establish general-purpose redaction of arbitrary legacy JSON or free text. Invalid JSON falls back to empty content; primitive legacy JSON and broader raw-input validation need separate resilience review.
- Investigation requests include pending/cancelled states while draft diagnostic content stays withheld. Verified report access alone creates no acceptance/ownership/escalation event. Offered/accepted handover, inactive owner escalation, correction/addendum history, pharmacy clarification, cashier reconciliation/refunds and attributable follow-up closure remain backlog.
- This batch reduces the source inventory's unclassified count from five to two (queues and supply documents). Regex detection and matching source hashes are not complete branch coverage. Whole-inventory strict acceptance and external custody/retention/security/clinical/legal/DHA/restore gates remain outstanding.

# Service assessment lifecycle and saved-record correction

20 October 2026 (Nairobi). This implements the lifecycle, failed-load and saved-record presentation portions of the previous assessment audit. It does **not** complete assessment revision protection or immutable assessment history, and is not production or clinical approval.

## Changed behavior

- Both assessment saves and patient-link commands use the existing clinical-open definition: DISCHARGED, COMPLETED, CANCELLED or a clinical-closure timestamp prevents writes. Assessment replacement also rejects any SIGNED or CORRECTED encounter, including an older final encounter beside a newer draft. No new draft may evade that final-state guard.
- The audited, facility-scoped GET includes CORRECTED records, authoritative visit state, a read-only flag and the recorder's display name. The response still returns at most the latest applicable encounter record, rather than claiming an assessment history. The final-encounter count prevents a newer draft from enabling edits when an older encounter is final. POST returns the recorder's display name on its saved record as well. Responses remain private/no-store; authorization and disclosure audit failure still prevent output.
- Entry fields stay disabled during loading, after load failure and for read-only responses. A keyboard-accessible retry loads the retained snapshot before enabling writes. Aborted/unmounted reads cannot update a newer workspace. Linking a patient refreshes relationships without replacing an existing typed assessment draft; recovery preserves that draft. Successful save and a failed subsequent worklist refresh have distinct messages.
- Entry and saved sections share field order and two columns, collapsing to one on phones. Empty fields say **Not recorded**; explicit negatives, zero and supplied unassessed text remain visible. The saved snapshot names the patient, patient/visit numbers, clinic, template, last recorder and facility-timezone timestamp. Its encounter state remains visibly distinct from saving a draft.
- Printing hides editable drafts, commands and surrounding workspaces. Only the retained saved snapshot, identity, attribution and missing-value labels print. Long saved text can flow across pages. A visit without a saved record prints an explicit absence message. Print output is a saved snapshot, not proof of signing, clinical review or a complete longitudinal record.

## Verification boundaries

Four lifecycle acceptance assertions were red on the original runtime before implementation. Final route tests also cover authorization, facility predicates, final-state guards, an older final encounter beside a newer draft, template/field validation, related-patient checks, fail-closed disclosure and modeled transaction failure. The existing disclosure mock was updated for the new selected lifecycle fields; no production fallback was introduced for invalid mock data.

`scripts/e2e-assessment-lifecycle.mjs` runs only in the existing guarded disposable workflow database. It checks actual role and cross-facility read/write denial; a forced audit insertion failure leaves visit, encounter, record, queues and assessment history unchanged; final/closed states reject replacement while retaining the attributed record. Closed states also reject patient linking. SQL establishes synthetic SIGNED/CORRECTED/DISCHARGED/timestamp fixtures; it does not exercise or approve clinical signing/discharge. Fixture queues are retired only after the unchanged-state assertions, so unrelated queue tests retain their original preconditions.

Browser scenarios use intercepted synthetic assessment responses for failed-load keyboard recovery, signed/corrected/closed read-only states, draft retention on conflict, saved confirmation after worklist failure, 1440/768/390/320 layouts and saved-only printing. The full suite includes existing real API workflows and MFA tests. Native concurrent assessment saves, simultaneous sign/closure, and signer revision invalidation remain unproved and belong to the next correction.

Retained setup/failure evidence: an initial command ran the legacy root test task rather than platform tests and hit its Windows SQLite cleanup EBUSY; the first native browser startup found the old checkout lacked the newly locked `pg` dependency; `npm ci` and Prisma generation restored the exact lockfile. A full unit attempt found the older disclosure mock missing the selected final-encounter count. The first populated native fixture passed the new lifecycle checks but left synthetic consultation queues active, causing the later CALL_NEXT guard to reject; scoped queue retirement fixed the fixture without weakening that assertion. All logs and both databases are retained. No blind rerun, added application retry or production change was used to hide these failures.

Final counts, build identity, canonical source archive, hosted CI and rendered-page evidence are recorded in `SERVICE-ASSESSMENT-LIFECYCLE-EVIDENCE.json` after verification.
